# Phase 7 — Report UX v3 (parity-plus with jest-coverage-report-action)

Reference: `jest-coverage-report-action` (vendored read-only at
`jest-coverage-report-action-main/`, git-ignored). Goal: every visual idea it
has, plus our diff/baseline/policy superpowers, in every report state.

## Gap analysis — why our comment reads "flat"

| Element (reference)                                                         | Theirs  | Ours today                                  |
| --------------------------------------------------------------------------- | ------- | ------------------------------------------- |
| **Status icon column** 🟢🟡🔴 per metric (with `St.?` legend link)          | ✅      | ❌ none                                     |

| Long-path shrinking (common-prefix folding)                                 | ✅      | repo-relative only                          |

Why the first live run looked extra-sparse: `policy: report-only` (no
thresholds → no compliance context) and a single history point (no sparkline
column). Both must degrade better: the status column falls back to fixed
bands (🟢 ≥80, 🟡 ≥60, 🔴 below — same defaults as the reference) when no
thresholds are configured.

What we keep that the reference lacks (do not regress): baseline store +
single-run deltas, any-format parsers, ratchet/override policy, 8-state
machine, JSON/HTML artifacts, history sparklines, monorepo rows, AI sections,
CLI.

## Stage 7.1 — Comment v3 visuals (the big one)

Steps: totals table → `| St. | Metric | Percentage | Covered/Total |` with
🟢🟡🔴 status (threshold-aware, banded fallback), delta+arrow inside the
percentage cell (`87.1% (+0.1% 🔼)`); state heroes become GitHub alerts —
`[!CAUTION]` gate failed (with the violation sentence, reference-style),
`[!WARNING]` tests failed/partial, `[!NOTE]` baseline recorded, regression
legend as `[!IMPORTANT]`; file paths linked to
`https://github.com/{owner}/{repo}/blob/{headSha}/{path}` and uncovered
ranges to `…#L88-L104`; footer `Report generated by [coverage-insight](repo) from `

- short-sha chip linking to the commit; per-file rows get the same status
  icon.

Accept: snapshot per state; side-by-side eyeball vs the two reference
screenshots; sparse-config run (no thresholds, 1 history point) still shows
status icons and counts.

## Stage 7.2 — Grouped spoilers in every delta state

Steps: after the changed-files table, two collapsibles rendered whenever a
baseline exists (including state passed): `🔻 Show files with reduced
coverage (N)` and `🐣 Show new covered files (N)`; rows reuse the status
icon + arrows; cap 25 rows each with "…N more" line; keep the full table
spoiler last.

Accept: passed-state snapshot shows both spoilers; truncation safe.

## Stage 7.3 — Test run section everywhere

Steps: extend `testFailuresSchema` with optional `numPassedTests`,
`numTotalSuites`, `numFailedSuites`; renderer adds a "Test suite run
success/failed" section in ALL states (success: "N tests passing in M
suites"); update `examples/extract-test-failures.js` to emit the new fields
from vitest/jest JSON; failure state keeps grouped suites + excerpts.

Accept: passed state shows the success line when test data present; absent
data renders nothing (no regression for users without `test-failures`).

## Stage 7.4 — PR diff annotations

Steps: new input `annotations: all|coverage|failed-tests|none` (default
`all`); via the existing check run, attach annotations: uncovered ranges in
**touched** files → warning annotations ("line(s) not covered by tests"),
failed tests → failure annotations at the test file; chunk by 50 per API
call (GitHub limit), cap 200; works only with `use-check-run: true` or a
dedicated check created when annotations are on.

Accept: mocked-octokit tests for chunking/caps/filters; e2e on this repo's
dogfood PR shows annotations in Files changed.

## Stage 7.5 — DX inputs (reference parity)

Steps: formalize `run-script` (stream output, never fail the report —
tests for both modes); add `working-directory` (chdir for config, coverage
paths, blob links), `custom-title` (replaces the H2 text, keeps the
marker), `icons: emoji|ascii|unicode` (string table like the reference's
strings.json — emoji default).

Accept: unit tests per input; README inputs table updated.

## Stage 7.6 — Polish & docs

Steps: long-path folding (common-prefix elision keeping last 3 segments,
tooltip-style full path in `title` via HTML link); shields badge image at
the top of the comment when the history branch has badges and the repo is
public (unicode fallback otherwise); README before/after screenshots;
document "first run has no trend — appears after 2 baselines".

Accept: 500-file truncation still under 65k; README shows the new comment.

## Order & sizing

7.1 → 7.2 → 7.3 are renderer-only (one session, biggest visible win).
7.4 annotations is action-side (one session). 7.5/7.6 follow. All states
share one skeleton: alert hero → totals (St./%/Counts) → changed files →
spoilers → state extras → test run → footer.
